## Task 2.1 & 2.3: Issue Type System Backend (SELESAI)

**Status:** COMPLETED

**File yang Dibuat:**
1. `backend/src/services/issueTypeService.js`
2. `backend/src/controllers/issueTypeController.js`
3. `backend/src/routes/issueTypeRoutes.js`

**Fitur yang Diimplementasikan:**
- CRUD operations untuk issue types
- Hierarchy validation (Epic > Story > Task/Bug > Subtask)
- Predefined system issue types (Task, Bug, Story, Epic, Subtask)
- Project-specific dan global issue types
- Prevention of deleting issue types with existing issues
- Issue type statistics (count of issues per type)

**API Endpoints:**
- GET `/api/issue-types` - List all issue types
- GET `/api/issue-types/:id` - Get single issue type
- GET `/api/issue-types/validate/hierarchy` - Validate hierarchy
- POST `/api/issue-types` - Create issue type
- PUT `/api/issue-types/:id` - Update issue type
- DELETE `/api/issue-types/:id` - Delete issue type

**Fungsi Utama:**
- `getIssueTypes(projectId)` - Get all issue types for project
- `getIssueTypeById(id)` - Get single issue type
- `createIssueType(data, context)` - Create new issue type
- `updateIssueType(id, data, context)` - Update issue type
- `deleteIssueType(id, context)` - Delete issue type
- `validateHierarchy(parentType, childType)` - Validate parent-child hierarchy
- `canHaveChild(parentType, childType)` - Check if parent can have child
- `canHaveParent(childType, parentType)` - Check if child can have parent
- `seedDefaultIssueTypes()` - Seed default system types
- `getIssueTypeStats(projectId)` - Get statistics

## Task 3.1, 3.2 & 3.4: Workflow Engine Backend (SELESAI)

**Status:** COMPLETED

**File yang Dibuat:**
1. `backend/src/services/workflowService.js`
2. `backend/src/controllers/workflowController.js`
3. `backend/src/routes/workflowRoutes.js`

**Fitur yang Diimplementasikan:**
- Workflow CRUD operations
- Workflow state management (add, update, delete states)
- Workflow transition management
- Transition conditions evaluation (permission, user_role, field_value, assignee)
- Transition validators (required_fields, field_format)
- Post-transition functions (update_field, send_notification, assign_user)
- Issue transition execution
- Default workflow creation for projects

**State Categories:**
- TODO
- IN_PROGRESS
- DONE

**Default Workflow States:**
- To Do (initial)
- In Progress
- In Review
- Done (final)

**Default Workflow Transitions:**
- Start Progress (To Do → In Progress)
- Request Review (In Progress → In Review)
- Approve (In Review → Done)
- Reject (In Review → In Progress)
- Reopen (Done → To Do)
- Complete (In Progress → Done)
- Stop Progress (In Progress → To Do)

**API Endpoints:**
- GET `/api/workflows` - List all workflows
- GET `/api/workflows/:id` - Get single workflow
- GET `/api/workflows/:id/details` - Get workflow with states and transitions
- POST `/api/workflows` - Create workflow
- PUT `/api/workflows/:id` - Update workflow
- DELETE `/api/workflows/:id` - Delete workflow
- POST `/api/workflows/default/:projectId` - Create default workflow

**State Endpoints:**
- GET `/api/workflows/:workflowId/states` - List states
- POST `/api/workflows/:workflowId/states` - Create state
- PUT `/api/workflows/states/:stateId` - Update state
- DELETE `/api/workflows/states/:stateId` - Delete state

**Transition Endpoints:**
- GET `/api/workflows/:workflowId/transitions` - List transitions
- POST `/api/workflows/:workflowId/transitions` - Create transition
- PUT `/api/workflows/transitions/:transitionId` - Update transition
- DELETE `/api/workflows/transitions/:transitionId` - Delete transition

**Issue Transition Endpoints:**
- GET `/api/workflows/issues/:issueId/transitions` - Get available transitions
- POST `/api/workflows/issues/:issueId/transitions/:transitionId` - Execute transition
